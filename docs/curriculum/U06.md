# U06 — Usable interfaces with React

**Foundations · Learning unassessed.** Build a usable interface with explicit loading, failure and keyboard behavior.

Prerequisites: U05. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

Learn semantic HTML and CSS layout before JSX. A button performs an action; a link navigates; a label names a control. React renders from props and state. Keep one owner for a state value and derive what you can calculate instead of duplicating it. Event handlers respond to actions; effects synchronize with external systems. Requests can load, succeed, return empty or fail. Show each state deliberately and preserve user input after failure. Older async responses can arrive after newer ones, so immediate-response tests are insufficient.

- Study HTML forms, box model, flex/grid, responsive widths and visible focus.
- Props carry data down; callbacks request change. Use stable IDs as list keys.
- A state update requests a render; it does not replace values inside the running handler.
- Test keyboard interaction and request ordering as well as the happy path.

## Worked example

```text
function Counter() {
  const [count,setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>Books read: {count}</button>;
}
```

The button already supports keyboard activation. The updater receives the prior state. A styled div would need additional semantics and interaction behavior.

## Debugging scenario

A slow save causes a duplicate task. Distinguish duplicate submission from duplicate rendering with network evidence.

Injected defects belong only in disposable copies with synthetic data and external effects disabled.

## If stuck
