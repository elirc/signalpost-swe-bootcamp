# U04 — HTTP and a small API

**Foundations · Learning unassessed.** Build and diagnose a small request-response service with explicit error behavior.

Prerequisites: U03. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

An HTTP request contains method, URL, headers and sometimes a body. A response contains status, headers and a body. JSON is a representation, not proof of valid input. Trace parsing, validation, domain logic and response separately. A network failure differs from a 400 or 500 response. Start with a single process and an explicitly temporary memory store; persistence comes next. Authentication establishes who is calling; authorization determines allowed actions. This local practice service uses synthetic data and does not claim real user authentication.

- Separate transport, domain rules and storage.
- Declare statuses, body limits, missing-object behavior and error shape.
- Catch an awaited failure at a boundary that can return useful feedback.
- Bind training services to loopback; never put credentials in logs.

## Worked example

```text
POST /notes with {"text":"Read a chapter"}
201 Created with {"id":"n1","text":"Read a chapter"}
Invalid text -> 400 with {"error":"Invalid text"}
```

The server assigns the ID and validates text. Malformed JSON fails parsing; a well-formed invalid object fails field validation. A failed connection has no HTTP response status.

## U04-02 — Build the task API

**SOLO · Build independently · 3–6 focused hours, provisional.**

Implement POST /tasks, GET /tasks and PATCH /tasks/:id/complete with a memory store. Apply U03 title/minutes policy; server creates IDs; new tasks start open. Use 201 for creation, 200 for read/complete, 400 invalid input, 404 missing ID and 413 for bodies above 16 KiB. Repeated completion preserves its first timestamp.

Acceptance:

- Exercise success, malformed JSON, body limit and missing ID through the HTTP boundary.

## Debugging scenario

The client shows success before awaiting a request that fails. Test the user-visible consequence.

Injected defects belong only in disposable copies with synthetic data and external effects disabled.

## If stuck
