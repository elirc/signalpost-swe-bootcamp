# U02 — Debugging and problem solving

**Foundations · Learning unassessed.** Turn an unclear failure into a small reproduction and a verified correction.

Prerequisites: U01. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

Start with a precise difference between expected and observed behavior. Reduce the input until the failure is easy to reason about. A hypothesis proposes a cause; an experiment should distinguish it from another cause. Inspect values at a boundary and change one thing at a time. Syntax errors prevent parsing, runtime errors interrupt execution and logic errors can produce plausible wrong answers. Decompose a problem into small operations with explicit contracts. Async work completes later: a Promise represents its eventual outcome, and await can throw when that work rejects.

- A minimal reproduction preserves the failure while removing unrelated code.
- Off-by-one errors, accidental mutation and string/number confusion deserve explicit experiments.
- Use a breakpoint or targeted log to inspect a hypothesis; remove debug noise afterward.
- A regression must fail under the old defect and pass after the correction.

## Worked example

```text
const samples = [2,4,6];
let total = 0;
for (let i = 0; i <= samples.length; i++) total += samples[i];
console.log(total); // observed: NaN
```

Indices 0, 1 and 2 exist; index 3 is undefined. Inspect i and samples[i] to distinguish a boundary error from invalid data. Changing the expected answer would conceal the defect.

## Guided practice

1. Reproduce the example unchanged; predict the first invalid iteration.
2. Inspect with a log or debugger and correct the boundary.
3. Write a regression for the original defect.
4. In a scratch async function, await Promise.resolve and Promise.reject; catch and explain rejection.

## Delayed transfer

A search fails only at the last item. Propose two different causes and an experiment separating them before editing.

Revisit after 2–7 days and around three weeks with the prior solution closed. These are scheduling defaults, not scientific mastery thresholds.

## Debugging scenario

A test passes alone but fails after another test. Investigate shared mutable state before adding a timeout.

Injected defects belong only in disposable copies with synthetic data and external effects disabled.

## If stuck

Reduce to two items. Trace indices and values, then reintroduce one condition at a time.
