# U03 — TypeScript and trustworthy tests

**Foundations · Learning unassessed.** Express valid states in types and verify behavior at runtime boundaries.

Prerequisites: U02. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

JavaScript is the runtime; TypeScript checks assumptions before execution. Type annotations do not validate external JSON. Treat external input as unknown, inspect it and narrow to a trusted type. A discriminated union expresses alternatives without contradictory boolean flags. Keep domain decisions in functions with explicit inputs and outputs. Tests should verify caller-visible behavior: ordinary cases, boundaries and failures. Unit tests isolate decisions; integration tests check real components working together. A mock does not prove that its real dependency behaves the same way.

- Learn object types, optional fields, unions and narrowing before advanced generics.
- Avoid any and unchecked assertions that hide a missing runtime check.
- Make time and randomness explicit inputs when testing decisions.
- Coverage alone does not establish that assertions detect meaningful failures.

## Worked example

```text
type Result = {kind:'found'; value:string} | {kind:'missing'};
function describe(result: Result): string {
  if (result.kind === 'missing') return 'No result';
  return result.value;
}
```

Checking kind narrows the union. value exists only in the found branch. The compiler cannot prove a network response has this shape unless the boundary validates it.
