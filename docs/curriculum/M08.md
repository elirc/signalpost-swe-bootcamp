# M08 — Reliability

Operate the correctness chain under failure.

Target competencies: observability, operational design. Provisional target rubric level: 4. Learning: unassessed.

## Working knowledge

An SLO needs a numerator, denominator, window and user-visible meaning. Alert on evaluator lag and undelivered pages, not just process health. Runbooks must say how to establish safety before replaying effects.

## Prerequisites

Complete prior milestone delivery and declared learning gates before claiming advancement. Independent work can be prepared in advance; no future milestone is credited by association.

## Study sequence

Read the relevant ADR and primary reference. Reproduce the smallest boundary behavior. Close the implementation before the SOLO exercise. Record a prediction before running it. Write the explanation from memory, then compare with observed behavior.

## Weekly practice

Reserve 30% of study time for drills. Every week: one no-AI hour and one independent planted-defect review. Rotate chaos, interview, code-reading, bad requirements and agent supervision. Use git bisect at least monthly.

## Adversarial scenario

A provider returns 200 for messages it never delivers. Identify what your current SLO can and cannot observe.

## Transfer assessment

Restore a backup into a fresh environment and reconcile alert state with previously sent pages.

## Demo and defense

Present a reproducible demo and failure. Defend an alternative, a concurrency/failure/scale boundary and the first expected breaking point. On a miss, preserve correct software, complete the smallest exposing exercise, then reassess with a changed example.

## Readiness gate

Link the writeup, exact reviewed commit, criterion evidence, learner transfer evidence and human feedback where required. Compare behavior to the declared target level; list what evidence does not establish. Never infer a hiring level.
