# U08 — Maintain code with other people

**Independent delivery · Learning unassessed.** Safely change unfamiliar code and leave a handoff another person can use.

Prerequisites: U07. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

Discover the existing contract before refactoring: enter through a public function, follow one path and run tests. A refactor preserves behavior; a feature changes it. Prefer a small comprehensible boundary over a speculative framework. Git conflicts require preserving both intended behaviors, not accepting one side blindly. Review findings need a trigger, evidence and consequence. Agents may draft work, but you remain responsible for the integrated behavior and must be able to reject a plausible patch.

- Use characterization tests before changing unfamiliar behavior.
- Choose abstractions from real repeated needs and dependency direction.
- Separate blocking defects from preferences in review.
- Delegate only bounded work whose result you can inspect and verify.

## Worked example

```text
Finding: PATCH /tasks/unknown/complete returns 200.
Contract: missing ID returns 404.
Impact: caller cannot distinguish no change from a saved task.
Verification: assert response and unchanged storage.
```

A useful finding provides a reproducible consequence. Confidence and stylistic preference cannot substitute for evidence.

## Guided practice

1. Rehearse branch, diff, log and a small conflict in a disposable Git repo.
2. Read one unfamiliar 50–150 line function from the prepared project at this stage.
3. Write a characterization check before changing an isolated copy.
4. Read AGENT_ENGINEERING.md and draft a bounded brief.

## U08-01 — Read and review an unfamiliar change

**PAIR · Learn with guidance · 3–6 focused hours, provisional.**

Map inputs, outputs and dependencies for a small change; review it with evidence.

Acceptance:

- Run original checks before edits.
- Separate observations, inferences and preferences.
- Name behavior that must remain stable.

Done:

- Acceptance checked against actual output and a learner-owned artifact.
- Help used recorded; learner explains behavior and limitations.
- Feedback and delayed transfer pending until performed. Agent-prepared code earns no learning credit.

Out of scope: Extra frameworks, real notifications, paid infrastructure and unrelated platform work. Use synthetic data and the smallest exercise that proves the skill.

## Delayed transfer

A second storage adapter must preserve API errors. Define a small contract check and apply it to both.

Revisit after 2–7 days and around three weeks with the prior solution closed. These are scheduling defaults, not scientific mastery thresholds.

## Debugging scenario

An agent changes twelve unrelated files for one bug. Assess scope and integrate only a change you understand.

Injected defects belong only in disposable copies with synthetic data and external effects disabled.

## If stuck

Write a behavior table for one function and make one safe edit first.
