# U10 — Reliability and operating a service

**Senior practice · Learning unassessed.** Reason about partial failure and operate a small service using observable evidence.

Prerequisites: U09. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

A service can commit while its caller never receives success. Retrying can repeat effects, so define stable request identity and an atomic persistence boundary before claiming idempotency. Bound payloads, queues and retries so overload is visible. Logs should connect symptoms to a user path without exposing secrets. Select a user-outcome SLI and consider needs and data before choosing an SLO. Restore practice matters as much as backup creation. Local drills develop reasoning but do not establish sustained production ownership.

- Distinguish retry attempts from logical application effects.
- Use timeouts and a bounded retryable/nonretryable policy.
- Readiness, liveness and user success measure different things.
- Incident notes connect impact, timeline, evidence and owned follow-up.

## Worked example

```text
Create request R -> task + receipt commit atomically.
Connection closes before success reaches the client.
Retry R with same payload -> prior result.
Retry R with changed payload -> conflict.
```

If task and receipt commit separately, a crash can leave one without the other. This logical deduplication does not prove an external notification reached a human.

## Guided practice

1. Draw success, pre-commit failure and response-loss paths.
2. Add request IDs and local error counts without logging secrets.
3. Read one prepared Signalpost invariant test after writing your own expectations.
4. Plan a synthetic drill in a disposable copy with stop/recovery criteria.

## Delayed transfer

A timeout follows a successful external effect. Explain what a database transaction cannot undo and propose deduplication or reconciliation.

Revisit after 2–7 days and around three weeks with the prior solution closed. These are scheduling defaults, not scientific mastery thresholds.

## Debugging scenario

Slow dependencies cause retries to multiply load. Explain how unbounded retries delay recovery.

Injected defects belong only in disposable copies with synthetic data and external effects disabled.
