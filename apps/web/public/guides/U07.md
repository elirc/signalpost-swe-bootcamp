# U07 — Own a complete feature

**Independent delivery · Learning unassessed.** Deliver a bounded feature from a written need through verification and review.

Prerequisites: U06. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

Independent delivery connects a user need to dependable behavior through small decisions. Plan a thin end-to-end slice, expose uncertainty and include failures in the estimate. Authorization belongs on the server; a hidden button is not protection. A local server-only test identity seam can test permission rules but does not establish production authentication. Use an established authentication integration before sharing private data with real users. A useful PR explains the final behavior, tradeoff, risk and observed verification.

- Write acceptance examples and non-goals before implementation.
- Check membership on every read/mutation, including guessed object IDs.
- Keep authentication separate from browser-selected user or project IDs.
- Plan verification, failure detection and recovery alongside the feature.

## Worked example

```text
Viewer V belongs to project A.
GET A tasks -> allowed.
PATCH A task -> denied.
GET guessed B task -> no B data.
A disabled edit button alone proves none of these server rules.
```

Direct API calls bypass the UI. A trusted synthetic principal in local tests is a seam, not a real sign-in system. Label that boundary honestly.

## Guided practice

1. Write a one-page project-collaboration brief.
2. Review a sample owner/editor/viewer permission matrix with a tutor.
3. Trace one existing learner request and locate the authority boundary.
4. Plan a small vertical slice, uncertainty range and fallback.

## U07-01 — Scope a reviewable feature

**PAIR · Learn with guidance · 2–4 focused hours, provisional.**

Define owner/editor/viewer permissions for listing, creating, completing and renaming. Use a server-only test identity seam locally.

Acceptance:

- Six allow/deny examples include another project.
- Browser-supplied identity is never treated as authentication.
- Estimate slices and name a concrete uncertainty.

Done:

- Acceptance checked against actual output and a learner-owned artifact.
- Help used recorded; learner explains behavior and limitations.
- Feedback and delayed transfer pending until performed. Agent-prepared code earns no learning credit.

Out of scope: Extra frameworks, real notifications, paid infrastructure and unrelated platform work. Use synthetic data and the smallest exercise that proves the skill.

## Delayed transfer

Add archived projects: readable, but no new tasks. Enforce the rule on direct API calls.

Revisit after 2–7 days and around three weeks with the prior solution closed. These are scheduling defaults, not scientific mastery thresholds.

## Debugging scenario

A viewer sends a handcrafted mutation despite the disabled button. Find the missing authority check.

Injected defects belong only in disposable copies with synthetic data and external effects disabled.

## If stuck

Reduce to two roles and one route. Prove denial before propagating policy.

## Readiness

Demonstrate both competencies on your own task and a changed example. Apply ASSESSMENT.md; ratings describe behavior, not job titles.

Keep small-exercise records to three lines: intention; result/artifact; help/next gap. Portfolio work also needs a plan, review and handoff.
