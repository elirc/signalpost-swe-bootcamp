# U11 — Design under uncertain requirements

**Senior practice · Learning unassessed.** Choose a proportionate design, expose assumptions and revise it as evidence changes.

Prerequisites: U10. Challenge-out requires evidence; see ASSESSMENT.md.

## Learn

Begin with users, constraints and failure consequences. Clarify the important decision before drawing infrastructure. Estimate capacity with units and ranges, then identify the dominant assumption. Compare a simple design with one credible alternative across consistency, complexity, cost and operation. Additional services add coordination boundaries; a modular monolith may suffice. A decision record should state when to reconsider it. Migration design must preserve behavior and include validation and recovery.

- Separate functionality from latency, availability, privacy and retention constraints.
- Rough arithmetic exposes questions; it does not manufacture a forecast.
- State ownership and consistency of data across boundaries.
- A spike resolves one uncertainty with a timebox and stopping criterion.

## Worked example

```text
2,000 users × 20 tasks/day × 500 bytes ≈ 20 MB/day raw payload.
Excluded: indexes, history, backups and peak traffic.
Start with app + relational store. Revisit on measured bottlenecks or team-boundary needs.
```

Explicit units make the estimate reviewable. Raw payload is not total disk usage; a daily average hides bursts. The design remains conditional.

## U11-01 — Turn vague needs into decisions

**PAIR · Learn with guidance · 4–8 focused hours, provisional.**

Card: “Tasks must never be lost, reminders must be instant, and it must be cheap.” Translate absolutes into testable needs. With no stakeholder, document provisional assumptions.

Acceptance:

- Separate facts, assumptions and unresolved input.
- Define a minimal slice and two non-goals.
- Show capacity arithmetic and uncertainty.

Done:

- Acceptance checked against actual output and a learner-owned artifact.
- Help used recorded; learner explains behavior and limitations.
- Feedback and delayed transfer pending until performed. Agent-prepared code earns no learning credit.

Out of scope: Extra frameworks, real notifications, paid infrastructure and unrelated platform work. Use synthetic data and the smallest exercise that proves the skill.

## Delayed transfer

Design a resumable import with record identity, progress, validation errors and bounded resource use before choosing a queue.

Revisit after 2–7 days and around three weeks with the prior solution closed. These are scheduling defaults, not scientific mastery thresholds.

## Debugging scenario

A stakeholder requests tenfold scale without usage data. Propose measurement and a bounded experiment before rewriting.

Injected defects belong only in disposable copies with synthetic data and external effects disabled.

## If stuck

Reduce to one user journey and failure; compare two choices in a five-row table.
